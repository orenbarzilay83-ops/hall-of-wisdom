## Critical integration finding — two routing authorities are still live

The AI/advisor path is canonical and fail-closed:

`questionId -> kashf-question-route-registry -> kashf-method-router -> kashf-canonical-reading-engine -> v57 knowledge -> AI-safe context`

It covers all 138 Question Bank IDs and never falls back from an unmapped Question ID to a broad topic.

The **client-visible Kashf reading is still generated by the older path** in `goral-app.js`:

`window.KASHF_ENGINE.buildKashfReading(kashfBoard, kashfTopicId, clientCtx)`

That older engine uses `kashf-question-router.js`, which currently has exact routes for only **30 / 138** questions. For the other **108** selected Question Bank questions, `resolveKashfQuestionRoute()` returns null and the legacy broad topic bundle remains eligible to execute.

Therefore the advisor/AI and the client-visible reading can reach different routing decisions for the same selected Question ID. This is now the highest-priority integration gap.

### Concrete example: q-money-source

Question Bank intent: “מאיפה יגיע הכסף?” — p179 Incoming Honor source-by-house method.

So the client-visible legacy path can be blocked while the canonical AI path can correctly execute the verified p179 method. This proves the two paths must be unified rather than patched independently.

## Next implementation gate — Phase 5B

Do **not** expand the AI prompt or add more inference before client output and advisor output share one routing authority.

Phase 5B must migrate selected Question Bank readings to the canonical engine:

1. A selected `questionId` is authoritative.
2. Build the canonical board from the four mothers.
3. Execute `buildKashfReadingByQuestionId()`.
4. If the route/method is blocked, show the canonical blocked state; never fall back to a topic bundle.
5. Keep free-topic/legacy execution only for explicit legacy/free-topic flows, not for a selected canonical Question ID.
6. Verify the 50 currently runnable Question-ID routes and representative blocked/repair/educational routes.
7. Only after this parity gate passes should the smart-advisor AI be expanded.

## Safety invariant

For a selected Question Bank ID there must eventually be exactly one operational authority for both visible reading and AI:

`Question ID -> canonical route -> one method -> v57 Hebrew -> one executor or explicit block`.

No second legacy topic decision may override, broaden, soften or contradict that result.
